# Security policy

## Поддерживаемые версии

Исправления безопасности публикуются для последнего релиза агента. Старые
релизы следует обновлять после проверки подписанного манифеста.

## Как сообщить об уязвимости

Не публикуйте детали уязвимости, токены, pairing-коды или логи в открытом issue.
Отправьте приватное сообщение владельцу репозитория или используйте
конфиденциальный Security Advisory GitHub. В сообщении укажите версию агента,
ОС, минимальный воспроизводимый пример и возможное влияние.

Ожидаемый срок подтверждения сообщения: 3 рабочих дня. После подтверждения
будут согласованы исправление, тест регрессии и дата публичного раскрытия.

## Границы безопасности

- Агент не принимает входящие соединения извне; локальный API привязан к
  `127.0.0.1` и защищён локальным токеном.
- В безопасном режиме нет произвольного shell-exec: операции проходят через
  именованный gateway. `setup_run_cmd` доступен только владельцу в активной
  root-сессии с таймером и blocklist.
- Исходящие запросы выполняются по HTTPS к настроенному endpoint. Данные
  профиля, telemetry и findings агрегируются; секреты и сырые логи не уходят.
- Релизный манифест проверяется Ed25519 public key, архив дополнительно
  проверяется SHA-256 и ограничениями tar traversal/link/device файлов.
- Не заменяйте встроенный release public key локальной настройкой в production.
  Приватный signing key должен храниться только в защищённом CI/release vault.

## Для операторов

Немедленно отзовите agent/bot token в Hive при подозрении на компрометацию.
Проверьте `systemctl status siteadmin`, журнал сервиса и `siteadmin status`;
не прикладывайте к обращению содержимое state/outbox.
